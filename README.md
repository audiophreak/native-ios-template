# native-ios-template

A [Copier](https://copier.readthedocs.io/) template that adds a **native SwiftUI iOS app** to a project generated by
[web-core-template](https://github.com/audiophreak/web-core-template) (with `auth=true` and `native_client=true`). It is
versioned independently (git tags `vMAJOR.MINOR.PATCH`) and is applied to the **same directory**: it owns `ios/` and the
answers file `.copier-answers.ios.yml`, and nothing else.

What the app is: sign in (or create a local account), the current session, a list of items with create, edit and delete,
loading and empty states, problem-details errors, sign out. Typed API client generated by Apple's Swift OpenAPI Generator
from the web project's OpenAPI contract; the session token lives in the Keychain; Debug may use cleartext to localhost,
Release requires https.

## Use it

Normally through the platform CLI (`devkit new NAME --profile native-ios --database postgres`, or `devkit native add PATH`
on an existing full-stack project). By hand, from the web project's root, with a clean git tree:

```sh
copier copy gh:audiophreak/native-ios-template . --vcs-ref vX.Y.Z --data app_name=my-app
```

Upgrade it separately from the web part (note the answers file, which is not Copier's default):

```sh
copier update --answers-file .copier-answers.ios.yml --vcs-ref vX.Y.Z
```

## Questions

| Answer | Default | Meaning |
|---|---|---|
| `app_name` | (required) | the web project's name; lowercase letters, digits, hyphens |
| `app_display_name` | title of `app_name` | the name under the icon |
| `bundle_identifier` | `com.example.<app_name>` | reverse DNS; a placeholder: choose yours before signing for a device |
| `debug_api_port` | `3000` | the Debug build talks to `http://localhost:PORT` |
| `release_api_host` | `api.example.com` | the Release build talks to `https://HOST`; a placeholder |

Invalid answers fail before anything is written. They are recorded in `.copier-answers.ios.yml`.

## Compatibility

Each release states the web release whose contract it was generated from (`tools/web_contract.json`, `CHANGELOG.md`).
The contract is copied into `ios/Contract/` and checked against the project's own `openapi/openapi.json` by
`ios/scripts/check-contract.sh`; `ios/scripts/sync-contract.sh` updates both. Toolchain: Xcode 26 or newer, iOS 17.0
minimum deployment target. See `docs/`.

## Releasing
